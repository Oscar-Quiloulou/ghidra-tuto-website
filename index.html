Guide Ghidra

Apprendre le reverse engineering avec Ghidra, pas à pas.

Introduction

Ghidra est un framework de reverse engineering développé par la NSA, publié en open source en 2019. Il permet d'analyser des binaires compilés (exécutables, bibliothèques) et de reconstruire du pseudo-code à partir d'assembleur.

Il est comparable à IDA Pro ou radare2, mais entièrement gratuit.

⚠️ Avertissement légal N'analyse que des binaires que tu possèdes, que tu as écrits, ou pour lesquels tu as une autorisation explicite (CTF, challenges légaux comme crackmes.one). Le reverse engineering de logiciels tiers peut violer les conditions d'utilisation ou la loi selon les pays.

1. Installation

  1. Installe un JDK 17 ou 21 (Ghidra ne fonctionne pas avec Java 8).
  2. Télécharge Ghidra depuis ghidra-sre.org ou la page GitHub officielle.
  3. Décompresse l'archive dans un dossier (pas besoin d'installeur).
  4. Lance le script ghidraRun (Linux/macOS) ou ghidraRun.bat (Windows).
  5. Au premier lancement, accepte la licence et choisis ton répertoire de travail.
💡 Astuce Si Ghidra ne démarre pas, vérifie que java -version renvoie bien 17+ dans un terminal. Le chemin du JDK peut être forcé dans support/launch.properties.

2. Importer un binaire

  1. Crée un projet : File → New Project → Non-Shared Project.
  2. Choisis un dossier et un nom de projet.
  3. File → Import File et sélectionne ton binaire (.exe, .elf, .so, .dll, .bin…).
  4. Ghidra détecte le format automatiquement. Vérifie l'architecture et clique OK.
  5. Double-clique sur le fichier importé pour ouvrir la vue d'analyse.

3. Analyse automatique

À l'ouverture, Ghidra propose la fenêtre Analyze. Accepte avec les options par défaut pour un premier passage.

L'analyse peut prendre de quelques secondes à plusieurs minutes selon la taille du binaire. Elle effectue notamment :

  • la détection des fonctions et de leurs bornes,
  • la reconstruction des chaînes de caractères,
  • l'identification des appels de bibliothèques,
  • la propagation des types et des symboles.
Binaire volumineux ? Décoche les analyseurs les plus lents (Decompiler Parameter ID, Aggressive Instruction Finder) pour un premier passage rapide.

4. Découvrir l'interface

Une fois l'analyse terminée, tu arrives sur la vue principale. Les fenêtres essentielles :

FenêtreRôle
Program TreesSections, segments et mémoire du binaire.
Symbol TreeListe des fonctions, imports, exports, labels.
ListingDésassemblage brut, instruction par instruction.
DecompilerPseudo-code C reconstruit, la vue la plus utile.
Data Type ManagerTypes définis, structures, énumérations.

Tu peux réorganiser ces fenêtres par glisser-déposer et sauvegarder la disposition avec Window → Save Layout.

5. Le décompilateur

Ouvre-le via Window → Decompiler si la fenêtre n'est pas visible. Place ton curseur sur une fonction dans le Listing ou le Symbol Tree et le décompilateur affiche son pseudo-code correspondant.

Le pseudo-code n'est jamais parfait (types approximatifs, variables nommées uVar1, local_10…), mais il est suffisant pour comprendre la logique.

💡 Conseil Le décompilateur s'améliore au fur et à mesure que tu renommes variables et fonctions. Chaque correction se propage dans les fonctions appelantes.

6. Navigation & XREFs

Les XREFs (références croisées) indiquent qui appelle une fonction, qui lit une variable, qui utilise une chaîne. C'est l'outil le plus puissant pour remonter un flux.

  1. Clique sur une fonction, un symbole ou une adresse.
  2. Clic droit → References → Show References to (ou Ctrl+Shift+F).
  3. La liste des appels apparaît en bas. Double-clique pour naviguer.
  4. Utilise le bouton back (flèche ←) pour revenir.

Pour aller directement à une adresse : touche G puis saisis l'adresse ou le nom du symbole.

7. Renommer & commenter

Renommer est l'activité principale du reverse engineer. Plus tu documentes, plus le code devient compréhensible.

8. Recherche

Trois recherches principales, accessibles depuis le menu Search :

  • Program Text — recherche dans les instructions et symboles (texte libre).
  • For Strings — liste toutes les chaînes du binaire, filtrables par regex.
  • Memory — recherche d'octets ou de motifs hexadécimaux.
💡 Astuce Les chaînes comme "Invalid password", "Access denied" ou des URLs sont souvent un excellent point de départ : remonte leurs XREFs pour tomber sur la logique de vérification.

9. Scripts

Ghidra est scriptable en Java et en Python (via Jython). Ouvre le gestionnaire avec Window → Script Manager.

Quelques scripts fournis par défaut très utiles :

  • FindCrypt — détecte les constantes cryptographiques (AES, SHA, RC4…).
  • ExportToC — exporte le pseudo-code en fichier C.
  • SearchStrings — recherche avancée de chaînes.

Tu peux écrire tes propres scripts et les exécuter directement depuis l'interface.

10. Patch & export

Ghidra permet de modifier le binaire analysé :

  1. Clic droit sur une instruction → Patch Instruction.
  2. Modifie l'assembleur (ou les octets via Patch Data).
  3. Pour sauvegarder : File → Export Program, choisis le format d'origine.
⚠️ Rappel Patcher un binaire tiers et le redistribuer peut être illégal. Réserve ça à tes propres programmes, aux CTF, ou à l'apprentissage local.

Bonnes pratiques

  • Copie de travail — analyse toujours une copie du binaire, jamais l'original.
  • Documente — note tes hypothèses dans un fichier texte à côté du projet.
  • Renomme tôt — même un nom approximatif (check_password) vaut mieux que FUN_00401234.
  • Snapshots de projet — utilise les snapshots Ghidra avant une grosse session de patch.
  • Malware — analyse en VM isolée, sans réseau, avec snapshot de restauration.
  • Reste légal — CTF, crackmes, tes propres binaires. Pas de cracking commercial.
🎯 Pour progresser Entraîne-toi sur des crackmes.one, des challenges picoCTF ou Root-Me (catégorie Cracking). C'est le meilleur terrain d'apprentissage.
