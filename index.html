Guide Ghidra Complet

Maîtriser le reverse engineering avec Ghidra : du premier lancement au scripting avancé, en passant par le debugging, l'automatisation et les environnements restreints.

Introduction

Ghidra est un framework de reverse engineering développé par la NSA, publié en open source en 2019. Il permet d'analyser des binaires compilés et de reconstruire du pseudo-code à partir d'assembleur. Il est comparable à IDA Pro ou radare2, mais entièrement gratuit et extensible.

Capacités principales : désassemblage, décompilation, graphes, scripting (Java/Python), debugging, version tracking, analyse comportementale (BSim), et bien plus.

⚠️ Avertissement légal N'analyse que des binaires que tu possèdes, que tu as écrits, ou pour lesquels tu as une autorisation explicite (CTF, crackmes.one). Le reverse engineering de logiciels tiers peut violer les conditions d'utilisation ou la loi selon les pays.

1. Installation & prérequis

Systèmes supportés

Ghidra fonctionne sur Windows, macOS et Linux. Il nécessite un JDK 17 ou 21 (Ghidra ne fonctionne pas avec Java 8).

Installation pas à pas

  1. Installe un JDK 17+ : sudo apt install openjdk-17-jdk (Linux) ou télécharge Adoptium (Windows/macOS).
  2. Télécharge Ghidra depuis ghidra-sre.org ou la page GitHub officielle.
  3. Décompresse l'archive dans un dossier (pas d'installeur).
  4. Lance ghidraRun (Linux/macOS) ou ghidraRun.bat (Windows).
  5. Accepte la licence et choisis ton répertoire de travail.
💡 Astuce Si Ghidra ne démarre pas, vérifie que java -version renvoie bien 17+ dans un terminal. Le chemin du JDK peut être forcé dans support/launch.properties.
✅ Nouveauté Ghidra 11.3+ Le support Python 3 natif via PyGhidra est désormais intégré. Plus besoin de Jython pour les scripts modernes.

2. Importer un binaire

  1. Crée un projet : File → New Project → Non-Shared Project.
  2. Choisis un dossier et un nom de projet.
  3. File → Import File et sélectionne ton binaire (.exe, .elf, .so, .dll, .bin…).
  4. Ghidra détecte le format automatiquement. Vérifie l'architecture et clique OK.
  5. Double-clique sur le fichier importé pour ouvrir la vue d'analyse.
💡 Astuce Pour les binaires avec debug info, Ghidra importe automatiquement les symboles et types DWARF, ce qui améliore considérablement la qualité du décompilé.

3. Analyse automatique

À l'ouverture, Ghidra propose la fenêtre Analyze. Accepte avec les options par défaut pour un premier passage. L'analyse effectue :

  • la détection des fonctions et de leurs bornes,
  • la reconstruction des chaînes de caractères,
  • l'identification des appels de bibliothèques,
  • la propagation des types et des symboles,
  • la détection des constantes cryptographiques (via analyseurs).
Binaire volumineux ? Décoche les analyseurs lents (Decompiler Parameter ID, Aggressive Instruction Finder) pour un premier passage rapide. Tu pourras les relancer plus tard sur des fonctions ciblées.

Re-analyser après modification

Si tu modifies des types ou des signatures, tu peux relancer l'analyse sur une zone sélectionnée : Analysis → Re-analyze Selection.

5. Décompilateur avancé

Ouvre-le via Window → Decompiler. Place ton curseur sur une fonction dans le Listing ou le Symbol Tree et le décompilateur affiche son pseudo-code.

Améliorer le décompilé

  1. Renomme les variables et fonctions (L). Le décompilateur propage automatiquement les noms dans les fonctions appelantes.
  2. Retype les variables (Ctrl+L). Un undefined8 peut devenir un HANDLE, LPVOID ou une structure.
  3. Définis des structures dans le Data Type Manager et applique-les aux pointeurs. Le décompilé devient beaucoup plus lisible.
  4. Corrige les signatures de fonctions via l'éditeur de signature (clic droit → Edit Function Signature ou ;).
  5. Ajoute des commentaires (touche ; ou clic droit → Comments). Ils survivent aux ré-analyses.
✅ Résultat Un décompilé bien annoté ressemble à du vrai code C : noms de fonctions explicites, structures claires, types corrects.

Limites du décompilateur

Le décompilé reste une reconstruction heuristique. Certains patterns (code obfusqué, assembleur inline, appels indirects complexes) produisent du code approximatif. Dans ces cas, compare avec le Listing assembleur pour vérifier.

6. Navigation & XREFs

Les XREFs (références croisées) indiquent qui appelle une fonction, qui lit une variable, qui utilise une chaîne. C'est l'outil le plus puissant pour remonter un flux.

  1. Clique sur une fonction, un symbole ou une adresse.
  2. Clic droit → References → Show References to (ou Ctrl+Shift+F).
  3. La liste des appels apparaît en bas. Double-clique pour naviguer.
  4. Utilise Alt+← pour revenir, Alt+→ pour avancer.

Pour aller directement à une adresse : G puis saisis l'adresse ou le nom du symbole.

8. Recherche avancée

Trois recherches principales, accessibles depuis le menu Search :

  • Program Text — recherche dans les instructions et symboles (texte libre).
  • For Strings — liste toutes les chaînes du binaire, filtrables par regex.
  • Memory — recherche d'octets ou de motifs hexadécimaux.
💡 Astuce Les chaînes comme "Invalid password", "Access denied" ou des URLs sont souvent un excellent point de départ : remonte leurs XREFs pour tomber sur la logique de vérification.

Recherche multi-binaires

Ctrl+Shift+S permet de chercher dans tous les programmes ouverts simultanément (utile pour les bibliothèques partagées).

9. Scripting (Jython & PyGhidra)

Ghidra est scriptable en Java, Python 2.7 (Jython) et depuis 11.3 en Python 3 natif via PyGhidra.

Jython (Python 2.7)

Scripts hérités, largement documentés. Structure typique :

# @category Examples
# @runtime Jython
from ghidra.app.script import GhidraScript

def main():
    println("Hello from Jython!")

if __name__ == "__main__":
    main()

PyGhidra (Python 3 natif) Recommandé

Nouvelle API utilisant CPython 3 via JPype. Accès complet à l'API Java de Ghidra avec la syntaxe Python moderne.

# @runtime PyGhidra
import pyghidra
from ghidra.program.flatapi import FlatProgramAPI

# Initialiser Ghidra
ghidra = pyghidra.Ghidra()

# Charger un binaire
ghidra.load_program("path/to/binary")

# Analyser
ghidra.perform_analysis()

# Accéder à une fonction
function = ghidra.get_function("main")
print(function.name)

# Exporter le décompilé
code = function.export_decompiled_code()
print(code)
✅ Avantages de PyGhidra
  • Utilise l'écosystème Python 3 (pip, venv, bibliothèques modernes)
  • Auto-complétion et type checking via ghidra.ghidra_builtins
  • Intégration VS Code avec édition directe, navigation et debugging
  • Scripts standalone exécutables hors du GUI

Scripts utiles fournis

  • FindCrypt — détecte les constantes cryptographiques (AES, SHA, RC4…).
  • ExportToC — exporte le pseudo-code en fichier C.
  • SearchStrings — recherche avancée de chaînes.
  • Function ID — identifie les fonctions de bibliothèques connues.
💡 Pour aller plus loin Consulte awesome-ghidra pour une liste curatée de scripts, plugins et outils communautaires.

10. Debugger intégré

Depuis Ghidra 11, un framework de debugging dynamique est intégré. Ghidra n'est pas un debugger en soi : il se connecte à des back-ends existants (GDB, LLDB, WinDbg).

Plateformes supportées

PlateformeBack-endArchitecture
LinuxGDBx86-64, arm64
macOSLLDBx86-64, Apple Silicon (arm64)
Windowsdbgeng (WinDbg)x86-64

Capacités principales

  • Trace Recording — enregistre l'exécution dans une base de données Trace, avec rembobinage pour revoir l'état historique.
  • Program Mapping — synchronise les vues statique et dynamique. Le curseur suit entre décompilé et exécution réelle.
  • Dynamic Listing — affiche la mémoire live, la pile, le tas, en temps réel.
  • Breakpoints — définition via clic droit, K, ou double-clic dans la marge.
  • Registers / Stack / Threads — inspection complète de l'état du processus.

Premiers pas

  1. Vérifie que les plugins Debugger sont activés : File → Configure → Configure All Plugins, filtre "Debugger".
  2. Charge le tool Debugger par défaut : Tools → Import Default Tools → Debugger.tool.
  3. Ouvre le binaire, puis clique sur l'icône Debug (bug) dans la barre d'outils.
  4. Sélectionne le launcher (gdb, lldb, dbgeng) et configure les options.
  5. Place des breakpoints et lance l'exécution.
⚠️ Performance L'enregistrement de trace peut être gourmand en mémoire. Pour les longues sessions, augmente le heap JVM dans support/launch.properties (ex : -Xmx8G).

11. Mode headless

Ghidra peut fonctionner sans interface graphique pour automatiser l'analyse de binaires en masse, dans des pipelines CI/CD ou des scripts.

Utilisation basique

# Analyser un binaire et exporter le décompilé
$GHIDRA_HOME/support/analyzeHeadless \
  /chemin/projet MonProjet \
  -import binaire.exe \
  -postScript ExportDecompiled.java \
  -scriptPath /chemin/scripts

Options utiles

OptionDescription
-importImporter un fichier
-processTraiter un fichier déjà importé
-postScriptExécuter un script après analyse
-preScriptExécuter un script avant analyse
-scriptPathRépertoire des scripts
-deleteProjectSupprimer le projet après traitement
-analysisTimeoutPerFileTimeout d'analyse par fichier (secondes)
✅ Cas d'usage Analyse automatique de malwares, scan de vulnérabilités, génération de rapports, comparaison de versions dans un pipeline.

12. Version Tracking & BSim

Version Tracking

Compare deux versions d'un même programme et propage automatiquement l'analyse (symboles, commentaires, types) de l'ancienne vers la nouvelle.

  1. Lance Version Tracking depuis le GUI : source = ancien exe, destination = nouveau exe.
  2. Clique sur la baguette magique pour exécuter tous les corrélateurs et appliquer les correspondances.
  3. Ghidra trie ensuite les matches. Tu peux interrompre et vérifier manuellement.
  4. Pour plus de matches, utilise un script PyGhidra post-traitement avec des seuils de similarité/confiance.

BSim (Behavioral Similarity)

Recherche de fonctions similaires entre binaires différents (pas seulement entre versions). Utile pour identifier des bibliothèques statiques, du code partagé ou des variantes de malware.

💡 Astuce BSim nécessite une base de données PostgreSQL. Configure-la dans Features/BSim avant utilisation.

13. Extensions & plugins

Ghidra est extensible via des plugins Java ou Python. La communauté en fournit des centaines.

🔐 FindCrypt

Détection de constantes cryptographiques (AES, SHA, RC4, etc.) dans le binaire.

🐹 gotools

Assistance pour le reverse engineering de binaires Go (récupération des noms de fonctions, types).

🌉 ghidra_bridge

Bridge Python 3 pour interagir avec Ghidra depuis un interpréteur externe (IPython, scripts).

🔗 ret-sync

Synchronisation entre Ghidra et un debugger externe (GDB, WinDbg, x64dbg).

📱 JNI Helper

Trouve et applique les signatures JNI dans les APK Android.

🧠 GhidrAssist

Extension LLM pour assistance AI dans le reverse engineering.

💡 Installation File → Install Extensions pour les extensions packagées. Pour les scripts, place-les dans ~/ghidra_scripts et rafraîchis le Script Manager.

14. Patch & export

Ghidra permet de modifier le binaire analysé :

  1. Clic droit sur une instruction → Patch Instruction.
  2. Modifie l'assembleur (ou les octets via Patch Data).
  3. Pour sauvegarder : File → Export Program, choisis le format d'origine.
⚠️ Rappel Patcher un binaire tiers et le redistribuer peut être illégal. Réserve ça à tes propres programmes, aux CTF, ou à l'apprentissage local.

Export vers C

Ctrl+E exporte la fonction courante en C. Utile pour analyser hors de Ghidra ou pour documenter.

15. Installation sans droits admin & contournement de restrictions

Sur un poste d'entreprise ou une machine verrouillée, plusieurs restrictions peuvent empêcher Ghidra de démarrer normalement :

  • Pas de droits administrateur (impossible d'installer un JDK dans Program Files ou de modifier PATH)
  • cmd.exe bloqué par stratégie de groupe
  • Les fichiers .bat et .cmd bloqués (AppLocker, Software Restriction Policies, WDAC)
  • Windows PowerShell soumis à une ExecutionPolicy restrictive

La solution : un launcher PowerShell

PowerShell est presque toujours disponible même quand cmd.exe est bloqué, et il n'est pas soumis aux mêmes restrictions d'extension que les .bat. On va donc réimplémenter entièrement ghidraRun.bat en PowerShell.

⚠️ Pourquoi ne pas juste appeler le .bat depuis PowerShell ? Si le blocage est fait par AppLocker/SRP/WDAC, c'est le noyau Windows qui refuse d'exécuter un .bat, peu importe qui l'appelle. Il faut donc rejouer la logique du script en pur PowerShell, sans jamais invoquer cmd.exe.

Étape 1 — Extraire Ghidra dans un dossier utilisateur

Sans droits admin, on n'installe pas dans Program Files. On extrait l'archive dans un dossier personnel :

C:\Users\TonNom\Documents\ghidra_11.3_PUBLIC\
C:\Users\TonNom\Desktop\ghidra_11.3_PUBLIC\

Étape 2 — Installer un JDK portable (sans admin)

Télécharge la version ZIP (pas le MSI) de Temurin 17 ou 21 : adoptium.net/temurin/releases/

Extrais-le où tu veux, puis définis JAVA_HOME dans ta session PowerShell :

$env:JAVA_HOME = "C:\Users\TonNom\Documents\jdk-21.0.2+13"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"

# Vérification
java -version
💡 Astuce Pour rendre JAVA_HOME permanent sans droits admin : 
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Users\TonNom\Documents\jdk-21.0.2+13", "User")
Cela écrit dans le registre utilisateur (HKCU), pas besoin d'admin.

Étape 3 — Créer le script PowerShell

Crée un fichier ghidraRun.ps1 à la racine de Ghidra (à côté de ghidraRun.bat) et colle le contenu suivant :

📄 Afficher le script complet (ghidraRun.ps1) 
<#
    ghidraRun.ps1 — Lanceur Ghidra alternatif en PowerShell
    Remplace ghidraRun.bat pour les environnements où :
      - l'utilisateur n'est pas administrateur
      - cmd.exe est bloqué par stratégie de groupe
      - les fichiers .bat et .cmd sont bloqués (AppLocker/SRP/WDAC)

    Usage : powershell -ExecutionPolicy Bypass -File .\ghidraRun.ps1
#>

param(
    [Parameter(ValueFromRemainingArguments = $true)]
    [string[]]$GhidraArgs
)

$ErrorActionPreference = "Stop"

# ============================================================
# 1. Répertoire d'installation
# ============================================================
$ScriptDir = Split-Path -Parent $MyInvocation.MyCommand.Definition
$GhidraDir = $ScriptDir
if ((Split-Path -Leaf $ScriptDir) -eq "support") {
    $GhidraDir = Split-Path -Parent $ScriptDir
}
if (-not (Test-Path (Join-Path $GhidraDir "Ghidra"))) {
    Write-Host "ERREUR : dossier 'Ghidra' introuvable dans $GhidraDir" -ForegroundColor Red
    Write-Host "Placez ce script à la racine de l'installation Ghidra." -ForegroundColor Red
    exit 1
}

# ============================================================
# 2. Mémoire (équivalent MAXMEM_DEFAULT du .bat)
# ============================================================
$MAXMEM_DEFAULT = ""   # vide = défaut JVM (1/4 de la RAM)

if (-not $env:GHIDRA_MAXMEM)     { $env:GHIDRA_MAXMEM     = $MAXMEM_DEFAULT }
if (-not $env:GHIDRA_GUI_MAXMEM) { $env:GHIDRA_GUI_MAXMEM = $env:GHIDRA_MAXMEM }

# ============================================================
# 3. Options JVM externes
# ============================================================
$VMArgs = @()
if ($env:GHIDRA_JAVA_OPTIONS)     { $VMArgs += ($env:GHIDRA_JAVA_OPTIONS     -split '\s+') }
if ($env:GHIDRA_GUI_JAVA_OPTIONS) { $VMArgs += ($env:GHIDRA_GUI_JAVA_OPTIONS -split '\s+') }

# ============================================================
# 4. Localisation de Java
# ============================================================
function Find-JavaExe {
    if ($env:JAVA_HOME) {
        $c = Join-Path $env:JAVA_HOME "bin\java.exe"
        if (Test-Path $c) { return $c }
    }
    $cmd = Get-Command java.exe -ErrorAction SilentlyContinue
    if ($cmd) { return $cmd.Source }
    $patterns = @(
        "$env:ProgramFiles\Eclipse Adoptium\*\bin\java.exe",
        "$env:ProgramFiles\Java\jdk-*\bin\java.exe",
        "$env:ProgramFiles\Microsoft\jdk-*\bin\java.exe",
        "$env:LOCALAPPDATA\Programs\Eclipse Adoptium\*\bin\java.exe",
        "$env:LOCALAPPDATA\Programs\Microsoft\jdk-*\bin\java.exe",
        "$env:USERPROFILE\.jdks\*\bin\java.exe",
        "$env:USERPROFILE\jdk-*\bin\java.exe"
    )
    foreach ($p in $patterns) {
        $hit = Get-ChildItem $p -ErrorAction SilentlyContinue | Select-Object -First 1
        if ($hit) { return $hit.FullName }
    }
    return $null
}

$javaExe = Find-JavaExe
if (-not $javaExe) {
    Write-Host "ERREUR : Java introuvable." -ForegroundColor Red
    Write-Host "Installez un JDK 17+ (portable possible) ou définissez JAVA_HOME." -ForegroundColor Yellow
    exit 1
}

# ============================================================
# 5. Construction du classpath
#    Ghidra/<Catégorie>/<Module>/lib/*.jar  +  support/*.jar
# ============================================================
$classpathParts = New-Object System.Collections.Generic.List[string]

$ghidraRoot = Join-Path $GhidraDir "Ghidra"
Get-ChildItem $ghidraRoot -Directory -ErrorAction SilentlyContinue | ForEach-Object {
    $catDir = $_.FullName
    Get-ChildItem $catDir -Directory -ErrorAction SilentlyContinue | ForEach-Object {
        $libDir = Join-Path $_.FullName "lib"
        if (Test-Path $libDir) {
            Get-ChildItem "$libDir\*.jar" -ErrorAction SilentlyContinue | ForEach-Object {
                $classpathParts.Add($_.FullName) | Out-Null
            }
        }
    }
}
Get-ChildItem "$GhidraDir\support\*.jar" -ErrorAction SilentlyContinue | ForEach-Object {
    $classpathParts.Add($_.FullName) | Out-Null
}

if ($classpathParts.Count -eq 0) {
    Write-Host "ERREUR : aucun JAR trouvé dans $GhidraDir." -ForegroundColor Red
    exit 1
}

$classpath = ($classpathParts -join ";")

# ============================================================
# 6. Assemblage des arguments Java
# ============================================================
$argString = "-cp `"$classpath`""
if ($env:GHIDRA_GUI_MAXMEM) {
    $argString += " -Xmx$($env:GHIDRA_GUI_MAXMEM)"
}
foreach ($a in $VMArgs) { $argString += " $a" }
$argString += " ghidra.GhidraRun"
foreach ($a in $GhidraArgs) {
    if ($a -match '\s') { $argString += " `"$a`"" } else { $argString += " $a" }
}

# ============================================================
# 7. Lancement
# ============================================================
Write-Host ""
Write-Host "  Ghidra Launcher (PowerShell)" -ForegroundColor Cyan
Write-Host "  ----------------------------" -ForegroundColor Cyan
Write-Host "  Installation : $GhidraDir"
Write-Host "  Java         : $javaExe"
Write-Host "  JARs         : $($classpathParts.Count)"
Write-Host "  Mémoire      : $(if ($env:GHIDRA_GUI_MAXMEM) { $env:GHIDRA_GUI_MAXMEM } else { 'défaut JVM' })"
Write-Host ""

# java.exe  = avec console (utile pour voir les erreurs)
# javaw.exe = sans console (recommandé en usage normal)
$javaLaunch = $javaExe

Start-Process -FilePath $javaLaunch -ArgumentList $argString -NoNewWindow -Wait

Étape 4 — Lancer Ghidra

Ouvre une fenêtre PowerShell (pas cmd) et lance :

cd C:\Users\TonNom\Documents\ghidra_11.3_PUBLIC
powershell -ExecutionPolicy Bypass -File .\ghidraRun.ps1
💡 Pourquoi -ExecutionPolicy Bypass ? Windows bloque par défaut l'exécution des scripts .ps1. Cette option contourne la restriction uniquement pour cette exécution, sans modifier la politique système (donc sans droits admin).

Alternative : raccourci Windows (double-clic)

Pour lancer Ghidra d'un simple double-clic sans passer par un terminal :

  1. Clic droit sur le bureau → Nouveau → Raccourci.
  2. Dans Cible, colle : 
    powershell.exe -ExecutionPolicy Bypass -NoProfile -WindowStyle Hidden -File "C:\Users\TonNom\Documents\ghidra_11.3_PUBLIC\ghidraRun.ps1"
  3. Nom : Ghidra.
  4. Pour l'icône : clic droit → Propriétés → Changer d'icône → sélectionne ghidraRun.ico dans le dossier Ghidra.

Si même PowerShell est bloqué

Dans ce cas extrême, plusieurs pistes de secours :

  • Lance javaw.exe directement depuis un raccourci .lnk, sans passer par un script. Construis la ligne de commande manuellement à partir des arguments de ghidraRun.ps1.
  • Utilise une VM locale (VirtualBox portable, Hyper-V si activé) où tu installes Ghidra sans restriction.
  • Clé USB bootable avec un Linux live (Tails, Ubuntu) : aucune restriction Windows ne s'applique.
  • Demande une exception à l'IT pour le dossier Ghidra — c'est la solution propre et durable si tu dois l'utiliser régulièrement.

Bonnes pratiques

  • Copie de travail — analyse toujours une copie du binaire, jamais l'original.
  • Documente — note tes hypothèses dans un fichier texte à côté du projet.
  • Renomme tôt — même un nom approximatif (check_password) vaut mieux que FUN_00401234.
  • Snapshots de projet — utilise les snapshots Ghidra avant une grosse session de patch.
  • Malware — analyse en VM isolée, sans réseau, avec snapshot de restauration.
  • Heap JVM — pour les gros binaires, augmente la mémoire : -Xmx8G dans launch.properties.
  • Reste légal — CTF, crackmes, tes propres binaires. Pas de cracking commercial.
  • Scripts versionnés — garde tes scripts dans un dépôt Git séparé.
🎯 Pour progresser Entraîne-toi sur des crackmes.one, des challenges picoCTF ou Root-Me (catégorie Cracking). C'est le meilleur terrain d'apprentissage.
